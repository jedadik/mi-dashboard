# JEDADI - Dashboard de Productividad

**Look always ahead** 👁️

JEDADI es un dashboard inteligente para gestionar tus tareas académicas y proyectos personales. Organiza tus pendientes, monitorea tu progreso y nunca más olvides una entrega.

## 🚀 Características

- **Dashboard interactivo**: Visualiza todas tus tareas y proyectos en un solo lugar
- **Organización por categorías**: Separa tus asignaturas académicas de tus proyectos personales
- **Sistema de prioridades**: Marca tareas como alta, media o baja prioridad
- **Seguimiento de progreso**: Ve el porcentaje de tareas completadas por categoría
- **Notas rápidas**: Guarda ideas y apuntes localmente para cada categoría
- **Autenticación segura**: Login con Supabase
- **Suscripción flexible**: Trial de 10 días, planes mensuales y anuales
- **Integración de pagos**: Procesamiento seguro con Wompi

## 📋 Requisitos Previos

- Node.js 18+ y npm/yarn
- Cuenta de Supabase
- Cuenta de Wompi (para procesamiento de pagos)
- Vercel (para desplegar la función serverless)

## 🔧 Configuración

### 1. Clonar el repositorio
```bash
git clone <tu-repo>
cd mi-dashboard
npm install
```

### 2. Configurar variables de entorno

Copia el archivo `.env.example` a `.env.local`:

```bash
cp .env.example .env.local
```

Luego completa las variables con tus valores:

```
VITE_SUPABASE_URL=tu-supabase-url
VITE_SUPABASE_ANON_KEY=tu-supabase-anon-key
VITE_WOMPI_CHECKOUT_URL=tu-wompi-checkout-url
VITE_WOMPI_URL_MENSUAL=tu-wompi-monthly-checkout-url
VITE_WOMPI_URL_ANUAL=tu-wompi-annual-checkout-url
VITE_APP_URL=http://localhost:5173
```

### 3. Configurar Supabase

#### Base de datos
Ejecuta las migraciones en tu proyecto Supabase:

```sql
-- Crear tabla profiles
create table public.profiles (
  id uuid references auth.users on delete cascade primary key,
  email text,
  subscription_status text default 'trial',
  plan_type text,
  subscription_end_date timestamptz,
  created_at timestamptz default now()
);

-- Crear tabla categories
create table public.categories (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users on delete cascade,
  name text not null,
  type text not null default 'university',
  created_at timestamptz default now()
);

-- Crear tabla tasks
create table public.tasks (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users on delete cascade,
  category_id bigint not null references categories on delete cascade,
  title text not null,
  due_date date,
  priority text default 'media',
  details text,
  is_completed boolean default false,
  created_at timestamptz default now()
);

-- Crear tabla payment_events
create table public.payment_events (
  id bigint generated by default as identity primary key,
  transaction_id text not null unique,
  event_name text not null,
  processed_at timestamptz not null default now()
);

alter table public.payment_events enable row level security;
```

#### Configurar Secrets en Supabase
En Supabase → Project Settings → Secrets & Keys, agrega:
- `WOMPI_EVENTS_SECRET`: Tu webhook secret de Wompi
- `WOMPI_MONTHLY_LINK_ID`: ID del link de pago mensual
- `WOMPI_ANNUAL_LINK_ID`: ID del link de pago anual

### 4. Configurar función Deno (Webhooks de Wompi)

La función Edge en `supabase/functions/wompi-webhook/` procesa los pagos de Wompi.

Despliega con:
```bash
supabase functions deploy wompi-webhook --project-id=tu-project-id
```

Configura el webhook en Wompi apuntando a:
```
https://tu-project-id.supabase.co/functions/v1/wompi-webhook
```

- Las contraseñas se validan con mínimo 6 caracteres
- Los webhooks de Wompi están firmados con SHA-256
- Las sesiones expiran después de 24 horas
- Las funciones Edge usan service role key para actualizar perfiles

## 🐛 Troubleshooting

### "Token expirado"
Los tokens de sesión se guardan en localStorage. Si ves este error, limpia el storage y vuelve a hacer login.

### Webhooks no se procesan
1. Verifica que el webhook secret sea correcto
2. Revisa los logs en Supabase → Functions
3. Asegúrate que la URL del webhook esté correctamente configurada en Wompi

### Suscripción no se activa
1. Verifica que `subscription_status` en la tabla `profiles` esté en 'active'
2. Revisa que `subscription_end_date` sea mayor que la fecha actual
3. Comprueba los logs del webhook
